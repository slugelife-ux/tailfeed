Price provenance

Every price batch we push carries receipts. A TLS-notary attestation proves the quote came from api.robinhood.com over a real TLS session — anyone can verify it, no trust in us required.

How it works

  1. For each push batch, we open notarized TLS sessions to api.robinhood.com/rhj/prices/<symbol> (TLS 1.2, real public certificate roots).
  2. TLSNotary's MPC-TLS protocol produces an attestation per symbol: a signed receipt committing to the entire session — server identity, handshake, request, full response.
  3. A presentation reveals the response; verification checks it against the attestation and Robinhood's real certificate chain.
  4. Both roots are anchored onchain: the Merkle root over keccak256(symbol ++ answer ++ generatedAt) leaves and the batch root over attestation digests.

Onchain anchor

0xE0101e17446F390EA1bc65297A8f6F98800b47A9 verified on explorer. Each anchor stores the two roots for one batch; the receipts below reconstruct them.

Verify a receipt yourself

# from the repo:
git clone https://github.com/slugelife-ux/tailfeed
cd tailfeed/provenance/gate && cargo build --release
./target/release/verify_proof proofs/<presentation file>

# or check the onchain anchor:
cast call 0xE0101e17446F390EA1bc65297A8f6F98800b47A9 \
  "anchors(uint256)(bytes32,bytes32,uint96,uint64)" <batch ts> \
  --rpc-url https://rpc.testnet.chain.robinhood.com

Verification is standalone and offline: the presentation file plus public certificate roots. No TailFeed server involved.

Honest limits

  • The notary currently runs in-process with TailFeed: the receipt proves the data came from Robinhood's API unmodified, but the witnessing notary is us. Production swaps in an independent notary.
  • Cadence: attested pushes run every 30 minutes — those rounds' onchain answers match the receipts exactly (same values, one source). The 5-minute heartbeat pushes between them serve freshness and deviation moves; their values come from the same API but without receipts. Receipt rounds are identifiable by the anchor timestamps onchain.
